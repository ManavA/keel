In-process defaults, external options

A package that talks to an external service also works without it. The external provider is selected by configuration, and the heavy dependency stays in a subpackage so importing the package does not pull in a client nobody asked for.

Example services

minimal (examples/minimal) — a notes API over Postgres and nothing else: config read and logged safely, password auth with verification and reset mounted next to the API, keyset paging, Postgres search with a reconcile job, an event-driven notification, and a shutdown that finishes in-flight requests. The tutorial is built on it.

fullstack (examples/fullstack) — the standard profile for keel new, extending the same shape with more of the packages wired together.

Architecture in one paragraph

Packages are layered, never siblings: a package may depend on the standard library, on third-party libraries, and on keel packages below it. Where two packages need each other, the connection is an interface the caller supplies — httpx.Health takes check functions and pg.HealthCheck returns one, so neither imports the other. The mechanical test: go get github.com/ManavA/keel/pg into a service with no HTTP server must compile. See ARCHITECTURE.md in the repo for the layout and import rules.
