Tutorial: your first keel service

Scaffold the notes example, run it against Postgres, and walk the API and the browser UI. You need Go 1.26 and Docker. Every command below was run to write this page.

1. Scaffold a project

From a keel checkout, keel new copies the minimal profile — a Postgres-backed notes API with local auth, search, a background job and a server-rendered web UI — into a new directory:

go run ./cmd/keel new notesapp -module example.com/notesapp
# created notesapp/ from keel's minimal profile: a Postgres-backed notes API
# with local auth, search, a background job and a server-rendered web UI.

Until keel has a published release, point the require at your checkout, then tidy and build:

cd notesapp
go mod edit -replace github.com/ManavA/keel=<path-to-keel>
go mod tidy
go build ./...

2. Start Postgres and serve

Only DATABASE_URL is required; every other default is chosen so the service comes up under a compose file holding an app and a database:

docker run -d --name keel-pg -e POSTGRES_USER=keel \
  -e POSTGRES_PASSWORD=keel -e POSTGRES_DB=keel -p 5432:5432 postgres:16
DATABASE_URL='postgres://keel:keel@127.0.0.1:5432/keel?sslmode=disable' go run .

The service applies its embedded migrations before it listens, then reports ready:

{"msg":"migrations complete","applied":2,"already_applied":0}
curl -s localhost:8080/readyz
{"status":"ok","build":{"revision":"unknown"},"checks":{"database":"ok","search":"ok"}}

3. Walk the API

Sign up for a bearer token, then create, list and search notes. Every notes request needs the token; without one the API answers 401.

TOKEN=$(curl -s -X POST localhost:8080/auth/signup \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"password123"}' \
  | python3 -c 'import sys,json; print(json.load(sys.stdin)["token"])')

curl -s localhost:8080/api/notes \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"title":"Roof repair quote","body":"Slate tiles, south side"}'
# {"id":"<uuid>","user_id":"<uuid>","title":"Roof repair quote",
#  "body":"Slate tiles, south side","created_at":"..."}

curl -s 'localhost:8080/api/notes?limit=2' -H "Authorization: Bearer $TOKEN"
curl -s 'localhost:8080/api/notes/search?q=tile' -H "Authorization: Bearer $TOKEN"

In development the verification link is written to the service log, so the signup → verify → login flow can be walked through from the terminal.

4. Open the browser UI

The same service serves HTML. The landing page at / needs no session; an unsigned visit to /app redirects to /login, while /notes without a session answers 401. Sign up through the form, follow the verification link from the log, and the dashboard lists the same rows the API just returned — the form writes through the same store, index and event path as a JSON create. A missing title is a 422 with the form re-rendered around a flash.

Pages are shells composed out of blocks; a fragment is a block rendered on its own for htmx, never a second copy. One stylesheet holds both themes — a page picks its with nothing but <html data-theme="..."> — and htmx is vendored with its version pinned.
