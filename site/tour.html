Package tour

Six stops across the tree. Every sample below is taken from the real packages and executed by site/tour_test.go, so the code you read is the code that runs.

1. retry — backoff with full jitter

retry.Do calls until success, a rejected error, cancellation, or the attempt budget, sleeping with full jitter between attempts. The zero options retry five times from a 100 ms base; Retryable decides which errors deserve another try.

calls := 0
err := retry.Do(ctx, func() error {
    calls++
    if calls < 3 {
        return errTourFlaky
    }
    return nil
}, retry.Options{MaxAttempts: 5, BaseDelay: time.Millisecond})
// err == nil, calls == 3

2. textpolicy — one guard for generated text

A policy normalizes text, then matches rules in order and reports the first hit. The error names the rule, never the text that tripped it, so a log line built from it is safe to paste into an incident channel. (The rule below is a placeholder token in the shape of the package's own examples, not a production list.)

policy := textpolicy.New(textpolicy.Rule{
    Name:    "spam-payout",
    Pattern: regexp.MustCompile(`(?i)\bfree-money-now\b`),
})
policy.Check("a note about the roof repair quote") // nil
err := policy.Check("claim your free-money-now prize today")
// err is *textpolicy.ViolationError with Rule == "spam-payout"

3. flags — percentage rollouts

Evaluation is pure and deterministic: the percentage check hashes the flag key with the subject, so the same pair always decides the same way and a rollout survives a restart. The memory store here stands in for the Postgres one; the decision function is the same.

store := flags.NewMemoryStore()
store.Upsert(ctx, flags.Flag{
    Key:     "new-editor",
    Enabled: true,
    Allow:   []string{"you@example.com"},
})
flag, _ := store.Get(ctx, "new-editor")
flags.Evaluate(flag, "you@example.com")      // true: allowlisted
flags.Evaluate(flag, "stranger@example.com") // false at 0%

4. jobs — outcomes computed from counts

A run's word is derived from what it counted rather than chosen by the code that logs the last line. An empty queue reports idle, not success; a run that had work and landed none of it reports did-nothing and exits non-zero, so a scheduler that only restarts non-zero exits retries it.

run := jobs.Outcome{Attempted: 3, Succeeded: 2, Failed: 1}
run.Status() // "partial"
jobs.Outcome{}.Status()              // "idle"
jobs.Outcome{Attempted: 2}.Status()  // "did-nothing"

The notes app's search-reconcile job reports its Outcome this way: an empty table logs idle rather than claiming success.

5. httpx — responses that do not leak

JSON writes a value with the status; a nil slice becomes [], never null, because null.length throws in browser clients. Error bodies carry the status phrase and a request id — never the input, the Go error, or the schema.

httpx.JSON(w, http.StatusOK, map[string]string{"title": "Roof repair quote"})
// {"title":"Roof repair quote"}

httpx.JSON(w, http.StatusOK, []string(nil))
// []

httpx.NotFound(w, r)
// 404 {"error":"not found"}

The notes API answers a missing note and a malformed id the same 404 way; the reason lives in the log line the request id leads to.

6. config — secrets stay out of logs

RedactURL strips credentials from a connection string and keeps the scheme, host, port and path — the username stays, because it identifies the database without authenticating to it. The example service logs its configuration at startup through config.Redacted, so DATABASE_URL appears with its host intact and its password replaced.

config.RedactURL("postgres://keel:s3cret@127.0.0.1:5544/keel?sslmode=disable")
// "postgres://keel:[redacted]@127.0.0.1:5544/keel?sslmode=disable"
config.RedactURL("") // "[unset]"
