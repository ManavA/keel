keel

Reusable Go packages for building a web backend: configuration, structured logging, HTTP serving, Postgres access and migrations, search, background jobs, events and transactional email. Each package is usable on its own, and every package that talks to an external service ships an in-process default, so a project running only Postgres gets a complete backend.

git clone https://github.com/ManavA/keel.git keel
keel new notesapp   # scaffold a service: see the tutorial

No published release yet: new projects point at a checkout with a replace directive (the tutorial shows how).

One service, two surfaces

The minimal example is a notes service over Postgres and nothing else: a JSON API (/api/notes, keyset pages, owner-scoped search) and a server-rendered browser UI (landing page, auth shells, notes dashboard) over the same store. A form post writes through the same store, index and event path as a JSON create, so the two surfaces list and search the same rows.

Conventions

  • No root package: importing github.com/ManavA/keel gets you nothing. Import the package you need.
  • Options are structs whose zero value works. Interfaces are small and declared where they are used.
  • Errors are wrapped with context. Context comes first. Logging goes through slog.
  • Packages that reach an external service take an in-process default, selected by configuration.
keel is a Go module at github.com/ManavA/keel. The tour samples are executed by site/tour_test.go; the gallery is rendered from the real templates by go generate ./site.
